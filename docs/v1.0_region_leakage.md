# v1.0 region-label leakage — finding & fix (2026-06-16)

## Summary
The v1.0 train/val/test split is built by **blocking on `RegionName`** (Dinerstein
ecoregion) so no ecoregion spans two splits (`scripts/create_splits.py`). The original
v1.0 `metadata.csv` **mis-assigned `RegionName` for ~59% of tiles** — the
`circumpolar_subregions.geojson` was cropped to the inference domain and a centroid
CRS step was off — so the spatial-block guarantee was violated and tiles leaked across
splits, **including into the held-out test set**. The data team's
`metadata_region_hotfix.csv` (Robb Young; confirmed by Heidi Rodenhizer) corrects
`RegionName`; this change applies it and regenerates a leakage-free split.

## Leakage measured (pre-hotfix split vs corrected regions)
- **13,219 / 22,259 tiles (59.4%)** had the wrong ecoregion.
- **3,494 tiles (303 positive)** sat in a split disagreeing with their corrected
  ecoregion's split; **35 / 49 corrected ecoregions spanned >1 split**.
- **Test contamination = 1,894 tiles (68 positive)**: 950 train tiles belonged to test
  ecoregions, 550 test tiles belonged to train ecoregions, +275/119 test↔val.

## Fix
1. `scripts/apply_region_hotfix.py` — left-join the hotfix `RegionName` onto our tile set
   (QC drops + all other columns preserved; imagery/labels untouched). Pre-hotfix
   metadata backed up (`metadata_pre_hotfix.csv` locally, `*.pre_hotfix` in GCS).
2. `scripts/create_splits.py --config configs/_resplit_v1_local.yaml` — regenerate the
   spatial-block split (seed 42) from corrected regions.
3. Upload corrected `metadata.csv` / `splits.yaml` / `splits_summary.json` to
   `gs://rts-mapping-v2/training/v1.0/`.

## Result (corrected, leakage-free)
- **0 ecoregions span >1 split**, 0 unassigned tiles.
- 49 ecoregions → train 40 / val 5 / test 4 regions.
- Tiles: train 1,513 pos / 16,438 neg · val 98 / 2,053 · **test 107 / 2,050** (≥100-test-pos constraint holds).

## Policy / impact (per user 2026-06-16)
- **No experiment reruns.** Phase-0 (μ₀=0.7912), Phase-3 loss/boundary, and Phase-5
  arch results were computed on the pre-hotfix (leaky) split → **absolute scores are
  optimistic**, but every candidate shared the same split so **relative gate comparisons
  are ~preserved**. We keep them, flagged "leaky-split, relative-only".
- **The corrected split is what makes the FINAL test honest** and is used going forward
  (Phase-4 EXTRA ablation, final lock). Normalization stats recomputed on the corrected
  train as part of the Phase-4 EXTRA norm pass.
- Imagery did not change, so no re-staging of tiles was needed.
