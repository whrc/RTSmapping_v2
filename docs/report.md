# Project report — rules

Defines the project's single living report: **`docs/report.html`**, generated by
**`scripts/build_report.py`** from MLflow. This `.md` is the *spec* (rules); the `.html` holds the
*content* (findings, figures, data). All findings — past, current, future — go in the report.

## Purpose & SSoT boundaries
- **`docs/report.html`** — the one place to look for project status + findings + insights. The dashboard.
- **`training/experiments.md`** — SSoT for the experiment *program* (phases, gate §1.4, ratios). The report
  *reflects* it; it does not redefine it.
- **`docs/phase*_*.md`** (§11.2: `phase0_baseline.md`, `phase2_data_scaling.md`, …) — the detailed text
  record per phase. The report summarizes/links these; deep numbers + rationale live there.
- Do **not** create competing findings lists elsewhere (that caused the 2026-06-07 planning error).

## Frequency — regenerate when
1. **After each run completes** (a queued experiment exits) — new rows/figures appear automatically.
2. **At every phase boundary** (a phase locks a winner or is skipped).
3. **On demand** before sharing/decisions.

One command (data sections auto-refresh from MLflow):
```bash
python scripts/build_report.py --config configs/phase0c_seed42.yaml \
    --tracking-uri file:///mnt/outputs/mlflow --output docs/report.html
```

## Contents — required sections
1. **Overview & status** — project one-liner, dataset version, **gate G**, current phase, key cards.
2–7. **Per phase (0→5)** — each MUST carry: results **numbers (table)** + at least one **figure** +
a one-paragraph **insight** + residual concerns. Phases without data show a `pending / blocked / gated`
badge with the reason.
8. **Findings & insights** — the cross-phase narrative (what we've learned, feasibility).
9. **Open questions / future / decisions** — what's next and what needs a human call.

Data sections are auto-generated from MLflow (by run_name prefix: `phase0a_arm`, `phase0b_lr`,
`phase0c_seed`, `phase2_scale_`, `phase3_loss_`, …). Narrative sections (8–9) and the embedded insight
boxes are **curated** in `build_report.py` — update them when regenerating after a finding changes.

## Format — strongly visual
- **Self-contained HTML** — figures embedded as base64 (no external files); opens anywhere offline.
- **Tables** for every set of numbers; **curves/bars** for every trend (data-scaling curve, train/val
  gap bars, loss curves, LR range curves).
- **Color-coded** gate outcomes (PASS green / no-grey) and status badges.
- **Figures, tables, and visuals are strongly preferred over prose.** Every phase with data gets a chart.
- Gate framing on every comparison: a candidate **wins** iff Δ(PR-AUC geomean) vs μ₀ ≥ `G = max(2σ₀,0.01)`
  **and** precision@recall0.5 does not regress (`experiments.md §1.4`).

## Viewing
`docs/report.html` is gitignored (generated). View via VS Code Live Server (`/mnt/outputs/report.html`
on port 5500) or open the file directly. The committed source of truth is `build_report.py` + the
per-phase `.md` docs; the HTML is regenerated, not hand-edited.
